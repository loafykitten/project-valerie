# Inference

The adapter provides authenticated model discovery and bounded Neuralwatt text replies and application tool calls from text or image input. Standard aliases use JSON; `-flex` aliases use buffered streaming with usage and actual tier/cost receipts. Inject a transport for offline tests. It does not retry potentially billed requests, execute tools, or deliver messages.

`discoverNeuralwattModels({ apiKey })` requires `customer` scope in both the authenticated response body and header. It returns normalized model limits, actual reasoning levels and aliases, and known prices. Unknown prices stay `null`. Settings validation uses the exact selected alias; a value accepted but mapped to no supported behavior is rejected.

`createNeuralwattClient({ apiKey, model, capabilities }).complete({ messages, maxTokens, temperature, reasoningEffort, signal })` pins a copy of the selected model capabilities and returns text, complete/partial status, actual usage details, and a bounded request ID. Temperature is optional (documented range 0–2); omission uses the provider default. Reasoning configuration requires verified capabilities. Internal reasoning text is discarded. Missing usage/cost is `null`, not zero; catalog pricing is informational and is never reported as an actual charge. A provider cost receipt is returned separately when supplied. Exhausting the output budget remains partial and must not be delivered as success.

Requests use a fixed provider origin, reject redirects, disable hosted tools, and enforce cancellation, a total deadline, 1 MiB of text content, 24 MiB of serialized request JSON, 2 MiB of JSON response data, and at most 32,768 completion tokens. Token estimation is a conservative UTF-8 text heuristic with template headroom, not the provider tokenizer. Safe errors discard provider bodies; 401/403, 429 and 413 have distinct codes, with bounded `Retry-After` metadata for rate limiting. Opaque 400 errors remain generic. The owner of a conversation decides whether to retry; the adapter never retries automatically.

`ChatMessage.content` accepts a string or ordered `{ type: "text", text }` / `{ type: "image_url", image_url: { url } }` parts. Image parts are permitted only in user messages with a pinned model advertising `vision: true` and a known `maxImages`. The URL must be a canonical base64 PNG/JPEG/WebP data URI with matching file signature. Remote URLs, extra part fields, unsupported formats, and malformed base64 are rejected or stripped before transport. Core owns image storage and dimension validation; the adapter does not decode full images. Limits are 5 MiB per image, 16 MiB total decoded image bytes, and 20 images or the provider's lower limit. Context estimation reserves 8,192 tokens per image; this is a planning allowance, not an exact vision-token bound or a billing estimate.

Primary API references: [chat completions](https://docs.neuralwatt.com/api/chat-completions), [model contracts and hosted tools opt-out](https://docs.neuralwatt.com/api/models), [Flex](https://docs.neuralwatt.com/guides/flex-tier), and [streaming accounting](https://docs.neuralwatt.com/guides/streaming). Exact tokenization and invoice reconciliation remain future work.

Flex streams have a 16 MiB wire limit, 256 Ki-character line/event limit and 1 MiB visible-text limit, with the same tool bounds and validated final completion shape as JSON. Keepalives do not extend the total deadline. A recognized finish reason plus `[DONE]` is required before text or tools are returned. Usage-only chunks, indexed tool fragments, UTF-8 boundaries and LF/CRLF/CR are supported. Internal reasoning is discarded. `serviceTier` is the actual provider receipt or `null`; `costUsd` is the reported `request_cost_usd` or `null`, never a catalog estimate. Known tier contradictions fail safely; unrecognized metadata stays unknown. No automatic standard fallback is performed. See [Flex behavior and activation](../../docs/features/flex-inference.md).

Application tool definitions are accepted through `complete({ tools })` only when the pinned authenticated model advertises `tools: true`. The adapter bounds schemas, tool counts and argument strings, rejects unrequested names, and returns normalized `toolCalls` with `finishReason: "tool_calls"` and `complete: false`. The server validates arguments and owns execution. Continuations use assistant `tool_calls` and matching `tool_call_id` results; missing, repeated or mismatched pairs fail before transport. Hosted tools remain disabled. Omit `tools` on the continuation to reject any further tool proposal.

The conversation image feature uses at most one image request and two model calls within a shared 120-second standard or 300-second Flex deadline. It persists the selected call, arguments, workflow and first-call usage before asking the model for its own acknowledgement. A retry resumes that stored outcome without selecting or enqueueing another image. Only the generated final acknowledgement is delivered; unconfirmed prose accompanying a tool proposal is discarded. Usage totals preserve unknown values as `null`, and the requesting turn's authored prompts and settings stay pinned throughout. Rejected arguments produce a generated explanation and factual activity record.

Live fictional acceptance on September 13, 2026: the authenticated account catalog exposed `glm-5.3-flash`, 1,048,560 context tokens, mandatory reasoning with `low`/`high`/`max`, and no separate published output ceiling. A four-message fictional gardening exchange plus Post-History Instructions completed with `low`, a 4,096-token output budget, a valid final reply on the requested topic, and no hosted tools or retries. Measured completion time was 1,403 ms; reported usage was 134 input and 27 output tokens (0 reasoning tokens reported). Actual cost was unavailable. This verifies a small fictional request; it does not measure latency with the full character prompt or prove long-context quality.

Run `bun scripts/inference-probe.ts check` for selected-model facts or `bun scripts/inference-probe.ts probe` for an explicitly authorized fictional live request. The script prints safe counts and status, never character content, message text, or credentials.

Image acceptance on September 13, 2026: authenticated `glm-5.3-flash` advertised vision and a 20-image limit. An in-memory synthetic 320×160 PNG containing a red circle and blue square was correctly described in order through `image_url.url` with a base64 data URI. The complete text reply took 722 ms; provider usage was 124 input and 19 output tokens, with actual cost unavailable. This verifies PNG understanding for the selected model, not full-resolution photo quality or every supported image format. Run `bun scripts/inference-image-probe.ts check` for capabilities or `bun scripts/inference-image-probe.ts probe` for the explicit fictional image probe. The public model documentation specifies vision and image limits; the exact data-URI multipart request shape was verified against the live API.
